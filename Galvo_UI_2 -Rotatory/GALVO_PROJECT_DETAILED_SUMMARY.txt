1.1 PURPOSE AND INDUSTRIAL APPLICATION
The Galvo Laser Scribing & Patterning System (also commercially designated as 
Galvo Studio and Patterning Machine) is an ultra-high-precision, industrial-grade 
computer-numerical-controlled (CNC) laser micromachining workstation. Developed 
by Spécialisé Products Private Limited (SPPL), the platform is engineered to 
execute microscopic material processing with sub-micron positioning repeatability 
and high-speed beam steering up to 10,000 mm/s.

Key industrial and scientific applications include:
- Laser scribing and micro-channel patterning for lab-on-a-chip and microfluidic 
  bio-devices (channel widths from 10 microns to 250 microns).
- Thin-film selective ablation and patterning on silicon wafers, solar cells, 
  and flexible polymer substrates.
- Direct-write printed circuit board (PCB) isolation routing and solder mask 
  ablation from Gerber RS-274X layout files.
- Surface texturing (creating micro-roughness from 100 to 250 micrometers for 
  biomedical implant osseointegration or mechanical friction enhancement).
- High-contrast, thermal-annealing black oxide marking on medical-grade stainless 
  steel (SS304/SS316L) and titanium.
- High-speed white frosting and ablation on anodized aluminum alloys.
- Low-thermal-damage contrast marking on engineering plastics (ABS, Delrin, PEEK).
- Dynamic serialization, 1D barcode, and 2D DataMatrix / QR code marking for 
  aerospace, automotive, and medical device traceability.

1.2 SYSTEM EVOLUTION & DUAL-ARCHITECTURE FRAMEWORK
The codebase embodies an evolution from a classic desktop Qt application 
into a modern, web-technology-driven industrial workstation:

A. Classic Qt Desktop Architecture (main.py):
   Built using Python 3.12 and PySide6 (Qt 6.6+), leveraging Qt Designer-compiled 
   interfaces (`interface.ui` -> `ui_interface.py`), custom widget styling 
   (`style.json`), and PyVista 3D OpenGL preview rendering (`preview3d.py`). 
   This foundation established full hardware drivers, serial communications, 
   calibration engines, and multi-threaded execution loops.

B. Next-Generation Modern Desktop Architecture (app.py):
   Built with a decoupled client-server architecture:
   - Frontend: A React 18, Vite 5, TypeScript, and Tailwind CSS single-page app 
     offering an industrial dark-themed UI (#09090b), interactive HTML5 Canvas 
     with live laser trajectory simulation, Web Audio acoustic feedback, and 
     sub-100ms real-time telemetry polling.
   - Host Runtime: PyWebView 5 embedding Microsoft Edge WebView2, exposing a 
     bidirectional asynchronous JavaScript-Python hardware bridge (`bridge.py` / 
     `GalvoHardwareBridge`).
   - Backend Engine: Direct native C++ DLL bindings to the Googol Technology 
     motion controller, integrated motion planners, vector parsers, and serial 
     subsystems.

1.3 KEY ENGINEERING CAPABILITIES & OPERATIONAL SCOPE
- Dual-Galvanometer high-speed beam scanning across calibrated fields (70x70 mm, 
  100x100 mm, 110x110 mm).
- Motorized Z-axis focal height adjustment with 333.333 steps/mm resolution 
  and 120 mm total vertical travel.
- Native ingestion of industry-standard vector files: AutoCAD DXF (R12 to modern), 
  Scalable Vector Graphics (SVG), and Gerber RS-274X PCB files.
- Multi-engine hatching algorithms: Bidirectional, Cross-Hatch (90° dual pass), 
  Contour Offset, and Auto-Rotating multi-pass layers.
- Full lens distortion correction supporting 9-point, 25-point, and 65x65 grid 
  binary correction tables (`.cor` files) to eliminate F-theta barrel, pincushion, 
  and trapezoidal distortions.
- Integrated machine vision camera for automated workpiece position detection, 
  rotation angle calculation, and fiducial alignment.
- Hardware-level Emergency Stop (E-Stop) with instant beam quench, DO1 cutoff, 
  and software latch protection.

2.1 LASER SOURCE & OPTICAL DELIVERY SYSTEM
The system is engineered to interface with pulsed industrial fiber laser sources, 
predominantly:
- Laser Source Type: Q-Switched Pulsed Ytterbium Fiber Laser / MOPA Pulsed Fiber Laser.
- Manufacturers: Raycus (RFL-P20QE / RFL-P30QS / RFL-P50QB), Maxphotonics (MFP-5W to 70W), 
  or JPT M1/M6/M7 series.
- Central Emission Wavelength: 1064 nm (Near-Infrared / NIR).
- Average Optical Output Power: 20 W to 50 W rated (software-tunable from 0% to 100%).
- Pulse Repetition Frequency (PRF): 20 kHz to 100 kHz (typically nominal at 20–80 kHz).
- Pulse Duration: 100 ns to 250 ns (Q-switched) or 2 ns to 500 ns (MOPA).
- Beam Quality factor: M² < 1.5 (TEM00 fundamental spatial mode).
- Collimated Output Beam Diameter: 6.0 mm to 7.5 mm.
- Red Pilot / Guide Laser: 635–650 nm visible red diode (<5 mW, Class IIIA) 
  co-axially aligned with the NIR fiber laser path for framing and positioning.

2.3 GOOGOL TECHNOLOGY GT5 / PROSYS U3 GALVO MOTION CONTROLLER CARD
The master hardware controller for coordinate positioning and motion interpolation:
- Controller Board: Googol Technology GT5 / ProSys U3 Series PCI/PCIe/USB Galvo Card.
- Galvo Control Protocol: Standard XY2-100 16-bit differential digital protocol 
  (Clock, Sync, Channel 1 X-data, Channel 2 Y-data) or Dual 16-bit Analog (+/- 10V).
- Coordinate Resolution: 16-bit signed integer (-32,768 to +32,767 bits, mapped 
  over nominal scan fields at 600.0 or 655.36 bits per millimeter).
- Maximum Scanning Speed: Up to 12,000 bits/ms (approx. 10,000 mm/s optical scan).
- Digital I/O Ports:
  - DO1 (Pin 33): Laser Gating / Modulation trigger signal.
  - DO2: Red Light Guide pointer control.
  - Analog Out (Pin 35): 0 to 5V or 0 to 10V DAC proportional power control voltage.
  - Stepper Axis 2: Pulse (PUL) and Direction (DIR) differential outputs for Z-axis.

2.4 NATIVE DLL DRIVER ARCHITECTURE (gt5motion_GT.dll)
Communication with the Googol Technology card is mediated via the Win32 C++ DLL 
`gt5motion_GT.dll` (with fallback to `gt5motion.dll`) loaded via Python `ctypes`:
- GT_PROSYS_U3_SetPass(12242): Authenticates and unlocks the board control registers.
- GT_PROSYS_U3_Initialize(byref(cards)): Detects and initializes installed cards.
- GT_PROSYS_U3_XY_Data(channel, dac_val): Writes 16-bit position data to galvo mirrors.
- GT_PROSYS_U3_Run_Galvo(mode): Starts execution of galvo trajectory interpolation.
- GT_PROSYS_U3_disable_hard_limit(axis): Disables hardware limit switch trip for Axis 2.
- GT_PROSYS_U3_ResetAxis(axis): Clears alarm registers and resets motor drive faults.
- GT_PROSYS_U3_set_pulse_out_mode(axis, mode): Sets pulse mode (0 = Pulse/Direction).
- GT_PROSYS_U3_Close(): Safely releases card hardware handles upon application exit.

2.5 STM32F411CEU6 BLACK PILL MICROCONTROLLER SUBSYSTEM
To bridge the Googol Technology card outputs with the DB25 laser bus, an STM32F411CEU6 
ARM Cortex-M4 32-bit microcontroller (Black Pill board) is deployed as a dedicated 
real-time signal conditioning coprocessor:
- Processor Core: ARM Cortex-M4 running at 96 MHz with hardware FPU.
- Firmware: Custom embedded C/C++ firmware (`lasertesting.ino` / `blackpillcode`).
- Input Conditioners:
  - PA0 (ADC Input): Wired to Galvo Card Pin 35 (via resistor divider to 0–3.3V). 
    Reads 12-bit ADC (0 to 4095) representing commanded laser power.
  - PA8 (High-Speed Digital Input): Wired to Galvo Card Pin 33 (laser modulation/gate).
- Output Drivers:
  - PB0 to PB7 (Digital Outputs): Wired directly to DB25 Pins 1–8 (D0–D7).
  - PB8 (Digital Output): Wired to DB25 Pin 9 (Latch). Pulses HIGH for 5 us when 
    power byte changes by >= 2 units (software hysteresis filter).
  - PB9 (Digital Output): Wired to DB25 Pin 19 (PA / Booster Gate). Duplicates 
    PA8 input with sub-microsecond latency, gating laser emission instantaneously.

2.6 MOTORIZED Z-AXIS STEPPER MOTION SUBSYSTEM
Focal distance and 3D depth engraving are managed by a precision motorized vertical stage:
- Actuator: NEMA 17 or NEMA 23 stepper motor paired with a precision lead screw.
- Motor Driver: Microstepping stepper driver configured for Pulse/Direction control.
- Hardware Drive Axis: Axis 2 on the Googol Technology motion card.
- Mechanical Calibration: Exactly 333.333 steps per millimeter (1 step = 3.0 microns).
- Travel Range: 0.0 mm (home focus) to 120.0 mm (maximum upper travel limit).
- Software Safety: Clamping checks in `stepper_controller.py` ensure commanded 
  positions never exceed 0.0 to 120.0 mm.
- Velocity & Timing: Default jog speed 1000 pulses/sec; rapid traverse 10,000 pulses/sec.

2.7 DUAL GALVANOMETER MIRROR SCANNER ASSEMBLY (GALVO 1 & GALVO 2)
The optical deflection head houses orthogonal galvanometer scanner motors:
- Galvo 1: Deflects optical beam along the Y-axis (or X depending on aspect configuration).
- Galvo 2: Deflects optical beam along the X-axis (default: Galvo 2 = X).
- Focusing Lens: F-Theta telecentric or standard field lens. Common focal lengths:
  - f = 100 mm: Produces a 70 x 70 mm marking field with ~20 um spot size.
  - f = 160 mm: Produces a 100 x 100 mm marking field with ~35 um spot size.
  - f = 210 mm: Produces a 140 x 140 mm marking field with ~45 um spot size.
- Mirror Coating: Dielectric high-damage-threshold coatings optimized for 1064 nm NIR.

2.8 MACHINE VISION & OPTICAL INSPECTION CAMERA SUBSYSTEM
An industrial digital camera is mounted co-axially or off-axis to provide computer vision:
- Interface: USB 3.0 / USB 2.0 DirectShow video stream capture via `FilterGraph`.
- Resolution: 1080p (1920x1080) or 5MP industrial CMOS sensor.
- Driver Architecture: `camera_thread.py` running an isolated `QThread` with OpenCV (`cv2`).
- Calibration Matrix: Calibrated camera-to-laser offsets (stored in `config.ini`):
  - Laser 1: X = +35.8 mm, Y = -7.6 mm
  - Laser 2: X = +84.5 mm, Y = -8.0 mm
- Vision Processing: Canny edge detection, Hough transform, and OpenCV template 
  matching (`cv2.matchTemplate`) to detect workpiece position, calculate rotation 
  angles, and apply 2D affine transformation matrices to marking coordinates.

6. END-TO-END OPERATIONAL WORKFLOW & WORKING MECHANISM
================================================================================
The execution lifecycle of a marking job proceeds through nine distinct phases:

6.1 PHASE 1: CAD INGESTION & VECTOR DISCRETIZATION
1. The operator imports a design file (DXF, SVG, or Gerber) or generates text/primitives.
2. If DXF: `DXFParser` extracts lines, arcs, circles, polylines, and splines. Splines 
   are discretized into chords using chordal tolerance limits.
3. If SVG: `parse_svg_paths_fast` parses SVG XML elements via `svgelements`. 
   Coordinates are converted from 96 DPI CSS pixels to physical millimeters 
   (scale factor: 25.4 / 96 = 0.264583 mm/px) and centered around (0, 0).
4. If Gerber: `gerber_parser.py` extracts copper traces and pads into boundary loops.
5. If QR/Barcode: Data is encoded into a 2D matrix, converted directly into 
   optimized rectangular solid modules, avoiding file bloating.

6.2 PHASE 2: COORDINATE TRANSFORMATION & OPTICAL DISTORTION CORRECTION
1. Global offsets (`offset_x`, `offset_y`), scaling (`scale_percent`), and rotation 
   (`angle`) are applied via 2D affine transformation matrices.
2. The coordinates pass through `core/coordinate_mapper.py`:
   - Axis swapping applied based on `galvo1_x`.
   - Inversion applied based on `g1_negate` / `g2_negate`.
   - Mathematical correction applied for barrel, pincushion, and trapezoid distortion.
3. If `.cor` correction table is loaded: Bilinear or bicubic interpolation calculates 
   the exact optical correction offset from the 65x65 grid table (`newest100mm.cor`).

6.3 PHASE 3: HATCH PATTERN GENERATION & SCANLINE SLICING
1. If hatching is enabled: The outer boundary polygon is intersected with a family 
   of parallel lines pitched at `line_spacing` (e.g. 0.05 mm) oriented at `angle`.
2. Clean line segments bounded inside the polygon are extracted.
3. If bidirectional: Alternating line directions are connected to minimize jump distance.
4. If cross-hatch: A second set of lines rotated by 90 degrees is added.
5. If contour marking: Perimeter passes are sequenced to mark before or after hatch fill.

6.4 PHASE 4: MOTION PLANNING & GALVO VECTOR QUEUE GENERATION
1. `core/motion_planner.py` compiles entities into a serialized command queue:
   - JUMP commands: Moves mirrors from current point to start of next segment 
     at `jump_speed` with laser OFF.
   - JUMP DELAY: Waits for mirror servo settling.
   - LASER ON DELAY: Opens laser gate.
   - MARK commands: Steers mirrors along vector at `mark_speed` with laser ON.
   - MARK DELAY / POLY DELAY: Stabilizes corner vertices.
   - LASER OFF DELAY: Closes laser gate.
2. Coordinates are converted from millimeters to 16-bit integer DAC bits 
   (typically 600.0 bits/mm).

6.5 PHASE 5: RED POINTER BOUNDING BOX FRAMING & OPERATOR VERIFICATION
1. Prior to firing, the operator clicks "Red Light Framing".
2. The system computes the overall bounding rectangle (Xmin, Ymin, Xmax, Ymax).
3. The motion controller turns ON the 650 nm red pilot diode and continuously sweeps 
   the galvo mirrors around the 4 outer perimeter corners at 1200 mm/s.
4. The operator physically inspects the red rectangle projected onto the workpiece 
   to confirm positioning, alignment, and scale.

6.6 PHASE 6: AUTOMATED CAMERA INSPECTION & ALIGNMENT
1. If machine vision alignment is active: The motorized stage moves workpiece beneath camera.
2. Camera captures image frame; OpenCV performs Canny edge detection or template matching.
3. System calculates translation offset (dx, dy) and workpiece rotation angle (theta).
4. Affine rotation and translation are injected into the motion planner, automatically 
   aligning the marking path to a crooked workpiece without requiring physical jigs.

6.7 PHASE 7: REAL-TIME LASER FIRING & MICRO-GALVO VECTOR EXECUTION
1. The operator clicks "Start Marking".
2. Commanded power (%) is output:
   - Googol Technology card outputs analog voltage on Pin 35.
   - STM32F411CE Black Pill reads ADC, updates 8-bit bus PB0-PB7, and pulses PB8 Latch.
   - DB25 sets internal laser power register.
3. Commanded frequency (kHz) and pulse width (ns) are configured.
4. Motion controller executes compiled vector queue via `gt5motion_GT.dll`.
5. For each mark command, Galvo Card Pin 33 triggers Black Pill PA8 -> PB9 -> DB25 Pin 19 
   (Booster Gate), firing the laser beam with sub-microsecond synchronization.

6.8 PHASE 8: MULTI-LAYER Z-AXIS STEPPING (DEEP ENGRAVING & TEXTURING)
1. If multiple loop passes are configured for deep engraving:
2. After completing Pass N:
   - Laser beam shuts OFF.
   - Controller issues pulses to Axis 2 stepper motor to lower Z stage by `z_drop_per_layer` 
     (e.g. 0.05 mm downward, keeping the laser beam focal waist at the newly excavated floor).
   - If `auto_rot` is enabled, hatch angle increments by `rot_angle` (e.g. +10°).
   - Pass N+1 executes.
3. Process repeats until total configured depth or loop count is achieved.

6.9 PHASE 9: JOB FINALIZATION & SAFETY PARKING
1. Upon queue completion, DO1 laser gate is clamped LOW, ensuring zero optical emission.
2. Red guide pointer is directed to configured park position (Top-Right or Galvo Center).
3. Telemetry reports `is_marking = False`, progress bar reaches 100%, and UI logs 
   "Job Completed Successfully".

7. SPECIALIZED INDUSTRIAL FEATURES & ALGORITHMIC IMPLEMENTATIONS
================================================================================
7.1 SURFACE TEXTURING (100 um TO 250 um)
- Generates controlled microscopic surface roughness for biomedical implants or mold grip.
- Operates at high frequency (60-80 kHz) and low-to-medium power (15-30%) combined 
  with dense cross-hatching to micro-melt the surface without deep cratering.

7.2 MULTI-LAYER DEPTH ENGRAVING WITH DYNAMIC FOCUS STEPPING (3 mm - 5 mm)
- Allows deep engraving up to 5 mm into metals (brass, steel, aluminum).
- Solves Rayleigh range defocusing by automatically driving the motorized Z-axis downward 
  after each layer pass, maintaining optimal power density at the bottom of the cut.

7.3 CURVATURE SURFACE MARKING (3D GALVO / Z-PROFILE DYNAMIC TRACKING)
- For marking on curved objects (cylinders, spheres, pipes).
- Mathematically projects 2D CAD vectors onto the 3D surface equation Z = f(X, Y), 
  calculating dynamic focal length adjustments sent to a 3D dynamic focusing unit 
  or synchronized Z-axis stage.

7.4 ROTARY MARKING ON CYLINDRICAL WORKPIECES (A-AXIS STEPPER SLICING)
- For 360-degree seamless marking around rings, tubes, and bottles.
- CAD geometry is sliced into narrow longitudinal strips (typically 0.5 to 2.0 mm wide).
- Slices are marked sequentially, interspersed with rotational stepper motor indexing commands.

7.5 AUTOMATED SERIAL NUMBER INCREMENT ENGINE
- Eliminates manual typing during batch manufacturing runs.
- Maintains integer counter state with customizable prefix, suffix, padding, and step size.
- Automatically re-synthesizes single-stroke vector outlines after each successful mark cycle.

7.6 LOW-OVERHEAD 2D QR CODE & 1D BARCODE SYNTHESIS
- Solves memory overload and DXF bloat by generating direct mathematical solid rectangles 
  for each module rather than heavy traced bitmap outlines, maintaining DXF sizes under 50 KB.

7.7 SINGLE-STROKE HERSHEY & TRUETYPE VECTOR FONT ENGINE
- Standard Windows TTF fonts produce double outline borders when marked.
- The system incorporates Hershey single-stroke centerline fonts and TrueType outline 
  hatching, enabling rapid marking of text and serial numbers in a single optical pass.

7.8 NON-BLOCKING MULTI-THREADED PAUSE, RESUME & EMERGENCY STOP ARCHITECTURE
- Python `threading.Thread` and Qt `QThread` isolate hardware communication from GUI event loops.
- `pause_marking()` sets an atomic boolean flag, immediately halts laser gating, and pauses 
  queue iteration without losing the current vector index.
- `emergency_stop()` executes an unconditional hardware beam cutoff, resets controller buffers, 
  and engages an operational safety lock.

7.9 F-THETA LENS CORRECTION GRID (.cor) INTERPOLATION MATHEMATICS
- Binary `.cor` files contain a 65 x 65 matrix of calibrated optical distortion coordinates.
- For any commanded coordinate (X, Y), the engine determines the bounding 4 grid points 
  and applies bilinear or bicubic spline interpolation to calculate the exact DAC correction 
  values (dX, dY), ensuring geometric accuracy better than 10 microns across the entire field.
